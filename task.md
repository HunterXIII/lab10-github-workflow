# Семинар 10. Задание 1. Полный цикл фичи в GitLab

## Общие правила из условия

- Группа из трёх человек работает в одном проекте GitLab.
- Ветка `main` защищена от прямого push. Изменения проходят через Merge Request.
- Для слияния нужен минимум один approve от другого участника.
- Обсуждения ведутся в комментариях GitLab.
- Каждый участник делает минимум два коммита и создаёт минимум один Merge Request.
- В конце нужен краткий отчёт в README.md или issue. В отчёте описывают выполненную работу, сложности и их решения.

## Задание 1

Цель — освоить командный процесс от issue до слияния изменений.

- A создаёт issue и реализует основную логику.
- B пишет тесты и проверяет крайние случаи.
- C проводит ревью, проверяет настройки защищённой ветки и выполняет слияние.

1. Создать проект GitLab. Защитить `main`, запретить прямой push и настроить обязательный Merge Request с минимум одним approve.
2. Создать issue с описанием небольшой фичи, например проверки email при регистрации.
3. Разделить работу на три подзадачи и создать ветки `feature/1-validation`, `feature/1-tests`, `feature/1-docs`.
4. В каждой ветке использовать Conventional Commits с префиксами `feat:`, `test:` и `docs:` соответственно.
5. Открыть три Merge Request. В каждом указать, что сделано, как проверить и `Closes #1`.
6. Оставить минимум два содержательных комментария в каждом MR. Автор отвечает, исправляет замечания и повторно отправляет изменения.
7. После approve слить MR в `main` и убедиться, что issue закрылась автоматически.
8. В README.md описать процесс и добавить ссылки на MR.

Проверяют ветвление и оформление MR, ревью и ответы на замечания, историю коммитов и защиту `main`.

Работа выполняется на GitHub. Pull Request соответствует Merge Request в исходном условии.
