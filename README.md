# Семинар 10. Проверка email при регистрации

В первом задании нужно провести небольшую фичу через issue, отдельные ветки, Pull Request, ревью и слияние в GitHub. Фича проверяет формат email при регистрации.

## Запуск

Нужен Python 3. Запуск из папки проекта после объединения кода и тестов:

```bash
python3 -B registration.py
python3 -B -m unittest -v
```

## Как работает проверка

`registration.py` запрашивает email и передаёт введённую строку в `is_valid_email`. Шаблон `name` проверяет часть до `@`, а `domain` проверяет домен. `re.fullmatch` требует, чтобы формату соответствовала вся строка. После проверки программа выводит один из двух результатов.

Пример из запуска:

```text
Введите email: first.last+lab@my-domain.example.org
Email подходит для регистрации.
```

```text
Введите email: first..last@example.com
Некорректный email.
```

В `test_registration.py` четыре тестовых метода. Они проверяют подходящие адреса, отсутствие обязательных частей, пустой ввод и пробелы, а также ошибки с точками и дефисами. Всего 13 адресов. Локальный запуск завершился с `Ran 4 tests` и `OK`.

## Работа с GitHub

Все три роли выполнил самостоятельно. Создал [issue #1](https://github.com/HunterXIII/lab10-github-workflow/issues/1) и отдельные ветки. В каждой есть исходный коммит и правки после саморевью.

- `feature/1-validation` — проверка формата email. [PR #2](https://github.com/HunterXIII/lab10-github-workflow/pull/2)
- `feature/1-tests` — тесты основных и крайних случаев. [PR #3](https://github.com/HunterXIII/lab10-github-workflow/pull/3)
- `feature/1-docs` — инструкция по запуску и отчёт. [PR #4](https://github.com/HunterXIII/lab10-github-workflow/pull/4)

В каждом PR оставил два замечания в рамках саморевью, отправил вторые коммиты с исправлениями и ответил на комментарии. В первой версии проходили адреса с двумя точками подряд в имени и с дефисом на краю части домена. Разделил имя на фрагменты между точками, уточнил шаблон домена и добавил пять примеров, которые ловят ошибки первой версии.

Каждый PR содержит `Closes #1`. При первом слиянии в `main` GitHub автоматически закрывает issue. [Автозакрытие issue](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue)

Репозиторий публичный. [Правило защиты main](https://github.com/HunterXIII/lab10-github-workflow/rules/26859646) запрещает прямой push и требует PR с одним approve. Для слияния нужен approve от другого участника. PR оставлены открытыми до его получения.

## Вопросы к защите

- **Что подтверждает проверка?** Что адрес соответствует формату этой учебной формы. Существование почтового ящика проверяется отдельно.
- **Что даёт `subTest`?** При сбое видно, на каком адресе упала проверка. Остальные примеры тоже проверяются.
- **Зачем защищать `main`?** Чтобы изменения попадали в основную ветку через PR и их можно было проверить перед слиянием.
